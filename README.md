# Kolkata Walkability Atlas

> Street-level **Perceived Walkability Scores (PWS)** for the city of Kolkata,
> derived from Google Street View imagery (Mask2Former computer vision) and
> stated-preference behavioural modelling.

A static web application inspired by
[CTstreets](https://miliasv.github.io/CTstreets/), built as part of the
**Integrated Active Mobility Safety Matrix (IAMSM)** PhD research at IIT
Kharagpur.

## Architecture in one paragraph

GitHub Pages serves only static files, so there is no live API. Instead, the
**backend** is a one-shot Python script that converts a raw PWS CSV into a
manifest plus a grid of small JSON "tiles". The **frontend** loads the
manifest, renders a sampled overview at low zoom, and lazy-fetches only the
tiles intersecting the current viewport at high zoom — keeping memory and
bandwidth low even for 400,000-point datasets.

See `docs/ARCHITECTURE.md` for the long version.

## Quick start

### 1. Prepare the data (one-time, or whenever the dataset updates)

```bash
cd backend
pip install -r requirements.txt
python process_data.py --input /path/to/aggregated_pixel_ratios.csv
```

This writes `manifest.json`, `overview.json`, and a `tiles/` directory into
`frontend/data/`.

### 2. Test locally

```bash
cd frontend
python -m http.server 8000
```

Open <http://localhost:8000>.

### 3. Deploy to GitHub Pages

1. Push the repository to GitHub (create the repo if needed).
2. In the GitHub UI: **Settings → Pages → Build and deployment → Source:
   GitHub Actions**.
3. Push to `main`. The workflow in `.github/workflows/deploy.yml` builds and
   deploys automatically. The site will be available at
   `https://<your-username>.github.io/<repo-name>/`.

For the full deployment walkthrough — including troubleshooting and custom
domain configuration — see `docs/DEPLOYMENT.md`.

## What's on the map

| Element | Meaning |
|---------|---------|
| Coloured dot | One sampling point along Kolkata's pedestrian network |
| Red → Green | PWS gradient: very poor → excellent walkability (0–100) |
| Click a point (zoom ≥ 14) | Inspect exact PWS, lat/lon, and rating |
| Score slider | Filter to show only points within a PWS range |
| Basemap toggles | Dark / Light / Satellite |

## Methodology (brief)

The Perceived Walkability Score per point combines four built-environment
indicators extracted from a Google Street View panorama via the **Mask2Former**
semantic segmentation model:

1. **Sidewalk** — share of pixels classified as walkable surface
2. **Greenery** — vegetation pixel ratio
3. **Streetlight** — presence of street lighting infrastructure
4. **Crowdedness** — density of pedestrians and vehicles

Indicator weights come from a **binary-logit stated-preference model**
calibrated on a survey conducted as part of the PhD research. The output is
normalised to a 0–100 scale where higher is more walkable.

Full methodology is documented in the registration report (not in this repo;
contact the author).

## Roadmap

This map is the visualisation layer for **Objective O1** of the IAMSM
research (extract street-level built-environment indicators). Planned next
steps:

- **O2** — Layer in VR-derived perceived-safety values per segment

  on Vercel/Render — outside the GitHub-Pages-only scope of this repo)
