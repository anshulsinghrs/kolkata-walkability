      About UrbanPulse

      UrbanPulse is an open-source platform for urban walkability and mobility intelligence. Search any city, layer OpenStreetMap data, recompute walkability scores under custom indicator weights, and overlay your own observations.

      The walkability score model combines built-environment indicators — sidewalk quality, greenery, lighting, crowdedness, crossing safety — weighted by a stated-preference coefficient set you can edit in the Weights tab.

      How to use

      1. Pick a city. Use the search bar at the top to jump to any place. The map fits to its OSM bounding box.
      2. Choose a basemap. In the Map tab, pick OSM, Positron, Dark, Satellite, or Topo.
      3. Upload your data. In the Data tab, drop a CSV or GeoJSON file. Headers are auto-detected — see the expected columns below.
      4. Style the layer. Switch between points, heatmap, or clusters in Layers, and tune the color scale.
      5. Tune the score. Adjust indicator coefficients in Weights to recompute walkability live.
      6. Export. Download the current view as GeoJSON, CSV, or PNG from the Export tab.

      CSV format

      Only latitude and longitude are required; everything else is optional. Common header variants are detected automatically (e.g. lat/lon, y/x, score for weight). 

      latitude,longitude,weightage,category,sidewalk,greenery,lighting,crowdedness,crossing_safety,notes,timestamp,image_url
22.5726,88.3639,72,audit,0.8,0.6,0.7,0.5,0.9,Broken kerb near junction,2025-03-14T10:21:00Z,https://…/kerb.jpg
22.5810,88.3501,38,hazard,0.3,0.2,0.4,0.9,0.2,Flooded sidewalk,,
      • latitude, longitude — required, decimal degrees. Aliases: lat, y / lng, lon, long, x.
      • weightage — 0–100 (or 0–1, auto-rescaled). Aliases: weight, score, pws, walkability, value. Defaults to 50 if missing.
      • category — free-form tag. Aliases: class, type, tag.
      • sidewalk, greenery, lighting, crowdedness, crossing_safety — indicator values (0–1 or 0–100).
      • notes, timestamp, image_url, hazard_type — optional metadata shown in the detail drawer.

      GeoJSON FeatureCollection files work too — point geometries are read directly and feature properties are matched against the same column names.
